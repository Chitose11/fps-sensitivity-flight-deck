Scope: single-file desktop web application at index.html. Visitor mode: Operate.

Audience and job: one returning FPS player calibrates personal mouse sensitivity for VALORANT, Overwatch 2, CS2, or Delta Force, completes five embedded tests, converts an equivalent physical turn distance between games, and compares results with local history.

Primary action and proof: select a game, start a new calibration, enter DPI and current sensitivity, optionally choose a ProSettings VALORANT player and target DPI as a physical-turn-distance starting point, measure a comfortable movement envelope, then test five experiment candidates at 65/82/100/122/150 percent with an explicit value-and-countdown cue before each switch, finish four fixed-crosshair angular tests plus one desktop micro-adjustment test, then receive one primary recommendation with low/high alternatives, eDPI, cm/360°, confidence, live and final evidence, an explanation, and equivalent recommendations for all four games. Switching games preserves cm/360° by default while warning that FOV and zoom behavior can still change perceived speed. A separate home converter accepts any supported source game, sensitivity, and DPI without requiring a test.

Chosen direction: Night-Flight Six-Pack. The first viewport is a trusted instrument panel with a direct last-result summary, one dominant start action, local history, and a full-width conversion bench. During tests the playfield dominates while eight compact live evidence values sit in the centered top HUD; each sensitivity switch pauses sampling for a two-second value-and-countdown cue. After testing, a large direct sensitivity value, compact facts, a four-game conversion list, and an evidence block replace the slower-to-read instrument cluster. Short mechanical sounds remain the memorable feedback.

Constraints: no login, upload, EXE, or external test; the deployable result is a multi-file static frontend and data stays in localStorage. Official game icons are embedded so the app does not hotlink at runtime. Static targets require a left-click hit confirmation and score accuracy, reaction, click error, path efficiency, and overshoot; tracking remains continuous dwell/error scoring. Timing uses monotonic elapsed time and pauses on focus or pointer-lock loss. Community-measured yaw/FOV values must be labelled non-official. WebHID access is read-only: Logitech HID++ and verified ATK vendor reports may expose configured DPI/report rate, while Razer and unsupported models fall back to identity plus clearly labelled browser-event measurement. Narrow screens may review results but cannot start unreliable aim tests.

Unresolved until implementation verification: exact palette tokens, typefaces, test normalization weights, future game-version parameter changes, vendor-protocol model coverage, and browser raw-input support.
